# End-User Communication: Common Copilot Issues and What To Do Next

## Version Header
- Date: 2026-08-13
- Author: DWP Engineering
- Audience: FinBridge end users
- Purpose: Explain common Copilot issues in plain English and provide immediate next steps

---

## Why you might see these issues
Most Copilot issues are caused by access settings, data indexing delays, or shared-content limitations, not a broken product. The good news is that most cases can be fixed quickly once we check the right thing first.

---

## Issue 1: "Copilot won't summarise a board pack in SharePoint, but I can open the file"
What this usually means:
- You can open the file in SharePoint, but Copilot may still be blocked by file permissions, sensitivity rules, or how access is granted in that location.

What you can do next:
1. Confirm you opened the exact same file version Copilot is being asked to use.
2. Check if the file is in a restricted folder/library (for example, board-only area).
3. If still blocked, raise an IT request with the file link and exact Copilot error text.

---

## Issue 2: "I started yesterday and Copilot in Outlook knows nothing about my recent emails"
What this usually means:
- New accounts can take time to fully index mailbox content, so Copilot may look "empty" at first.

What you can do next:
1. Wait a short period and try again later the same day.
2. Make sure you are signed into your work account in supported Outlook.
3. If no improvement by next working day, contact IT with your start date and screenshot.

---

## Issue 3: "Copilot says it doesn't have access to my salary review spreadsheet"
What this usually means:
- The file is protected by sensitivity labels or restricted access. This is expected for highly confidential HR data.

What you can do next:
1. Confirm whether that file is intentionally restricted.
2. Use approved HR reporting workflows for sensitive salary data.
3. If you believe access is incorrect, request a permission review through HR/IT.

---

## Issue 4: "Copilot in Teams can't find a client contract shared via a guest link from another organisation"
What this usually means:
- Guest/external links often sit outside your organisation's normal indexed content boundary.

What you can do next:
1. Open the contract directly from the shared link to verify access still works.
2. Ask the document owner whether an internal copy should be placed in an approved FinBridge workspace.
3. Re-run your Copilot prompt after the content is in an internal, accessible location.

---

## Issue 5: "Copilot stopped working for the whole Finance team today"
What this usually means:
- This may be a broad licensing/service/configuration change rather than an individual user issue.

What you can do next:
1. Check with your team lead if others are seeing the same issue.
2. Report as a priority incident to IT Service Desk (include team scope and start time).
3. Continue business-critical work using normal manual processes while IT investigates.

---

## Issue 6: "Copilot summarised a file I forgot I had access to"
What this usually means:
- Copilot can use content you are permitted to access, even if you do not remember that permission.

What you can do next:
1. Review the folder and check whether your access is still needed.
2. Ask your manager or data owner to remove unnecessary access.
3. Report suspected oversharing to IT/security so permissions can be cleaned up.

---

## Issue 7: "Copilot gives generic answers and ignores our SharePoint content"
What this usually means:
- Common causes are missing prerequisite setup (license/client), missing access, or content not yet indexed.

What you can do next:
1. Sign out/in and confirm you are using your work profile.
2. Test with one known file you can open in SharePoint and ask Copilot about it by name.
3. If still generic, contact IT and include one example prompt plus expected file source.

---

## Issue 8: "Copilot in Outlook can't see a shared mailbox calendar I manage for my director"
What this usually means:
- Delegated/shared mailbox scenarios do not always behave the same as your primary mailbox in Copilot.

What you can do next:
1. Confirm delegated calendar permissions are still active.
2. Try the task from your primary mailbox context first.
3. If this is a business-critical workflow, raise an IT ticket marked "shared mailbox Copilot scenario".

---

## Before contacting support, include these details
- App and platform (Outlook/Word/Excel/Teams, desktop or web)
- Exact error text shown by Copilot
- File or mailbox location (link/path if possible)
- Time issue started and whether others are affected
- Screenshot (if allowed by policy)

Providing these details helps IT resolve issues faster and avoids repeat troubleshooting.
